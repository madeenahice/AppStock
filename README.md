# ระบบจัดการสต๊อกยาและเวชภัณฑ์

เว็บแอปสำหรับเช็คสต๊อก 7 หน่วย พร้อมหน้า Home และ Dashboard เมนูเรียงดังนี้:

- Home
- Med Stock
- IV Fluid
- Equipment
- CPR Box
- Emer medicine
- Emer cart Adult
- Emer cart PED
- Dashboard

ชื่อหน่วยเดิมในข้อมูลที่บันทึกไว้และไฟล์ JSON จะถูกแปลงเป็นชื่อใหม่อัตโนมัติ เพิ่มรายการได้ด้วยปุ่ม +

## รายการต้นฉบับ

ดึงข้อมูลจากไฟล์ “รายการเช็คของ RN” แท็บ “ต้นฉบับข้อมูล” เมื่อ 8 กันยายน 2026 โดยจับคู่คอลัมน์ดังนี้:

| หน้า | คอลัมน์รายการ/Stock | จำนวนแถว |
|---|---|---:|
| Med Stock | I:J | 17 |
| IV Fluid | K:L | 13 |
| Equipment | M:N | 9 |
| CPR Box | C:D | 18 |
| Emer medicine | A:B | 17 |
| Emer cart Adult | E:F | 48 |
| Emer cart PED | G:H | 60 |

รวม 182 รายการจากต้นฉบับ 204 แถว โดยรวมแถวที่ชื่อและจำนวนเหมือนกันตามคำสั่งผู้ใช้ เหลือ IV Fluid 13 และ Equipment 9 รายการ รายการชื่อเหมือนกันแต่จำนวนต่างกันยังแยกไว้ ส่วน Thermo trace peripheral ใน Emer cart PED ใช้จำนวน 3 ตามคำตอบของผู้ใช้ แม้ H61 ในชีทจะว่าง

ข้อมูลดิบเก็บใน `source-sheet.json` และสร้างรายการแอปด้วย `node scripts/build-seed.cjs` นี่เป็นข้อมูลที่ดึงมา ณ วันที่ระบุ ไม่ใช่การอ่านชีทสดทุกครั้งที่เปิดหน้าเว็บ

เมื่อเปิดแอปหลังเปลี่ยนแหล่งข้อมูล ระบบปรับรายการตามต้นฉบับและสำรองข้อมูลชุดเดิมไว้ใน localStorage คีย์ขึ้นต้น `med-stock-before-source-` รายการที่ชื่อจับคู่กันได้จะคงจำนวนที่นับ วันหมดอายุ และข้อมูลการตรวจไว้ รายการที่ไม่ตรงต้นฉบับยังอยู่ในสำรอง ส่วนประวัติการตรวจเดิมยังคงอยู่ ข้อมูล cloud รุ่นเก่าจะผ่านการปรับรายการแบบเดียวกัน

จำนวน Stock จากชีทใช้เป็นจำนวนที่ต้องมี รายการใหม่เติมค่าเริ่มต้นในช่องจำนวนที่นับเท่าจำนวนที่ต้องมีตามพฤติกรรมเดิมของแอป แต่ยังไม่มีวันที่ตรวจหรือผู้ตรวจ ผู้ใช้ต้องตรวจนับจริงก่อนบันทึก

ทุกหน้าสต๊อกมีวันที่ตรวจเช็ค ช่วงเวลา (เวรดึก / เวรเช้า / เวรบ่าย) และชื่อผู้ตรวจเช็ค เลือกชื่อเดิมจาก dropdown หรือเลือกเพิ่มชื่อใหม่ ระบบจำชื่อหลังบันทึกและรวมชื่อจากประวัติเดิม

## Google Sheets และปีงบประมาณ

ปลายทาง: https://docs.google.com/spreadsheets/d/13b74zWOyP5WgnAF1HdrCE2IY6pFXifhcm5N27iq-pgY/edit

การแก้ไฟล์ในโปรเจคยังไม่อัปเดต Apps Script ที่ deploy อยู่ ต้องติดตั้งโค้ดใหม่ก่อนใช้การแยกปีงบประมาณ:

1. ใช้บัญชีที่มีสิทธิ์แก้ไขชีท เปิด Extensions → Apps Script
2. วางโค้ดจาก `google-sheets-web-app.gs` ลงในโปรเจค Apps Script ที่ใช้กับเว็บแอป
3. Deploy → Manage deployments → Edit → New version → Deploy โดยให้รันด้วยบัญชีเจ้าของที่เข้าถึงชีทปลายทางได้ และตั้งสิทธิ์เข้าถึง Web App ให้เหมาะกับผู้ใช้เว็บ
4. ถ้าเป็น deployment ใหม่ ให้นำ URL ที่ลงท้าย `/exec` ไปใส่ช่อง Google Sheet Web App URL ในการตั้งค่าของเว็บทุกเครื่อง
5. บันทึกการตรวจหนึ่งรายการ แล้วตรวจว่าแท็บหน่วยและ `Inspection Logs` ของปีนั้นมีข้อมูลตรงกับวันที่ เวร และผู้ตรวจ

ปีงบประมาณคำนวณจาก **วันที่ตรวจที่เลือก** ไม่ใช่วันที่กดบันทึก เช่น 30 ก.ย. 2026 เป็นปี 2569 และ 1 ต.ค. 2026 ถึง 30 ก.ย. 2027 เป็นปี 2570

- `Inspection Logs 2570`: สรุปการตรวจของปีนั้น
- `Emer medicine 2570` (และชื่อหน่วยอื่น): รายละเอียดรายการแยกหน่วยและปี
- `App State`: สถานะสต๊อกปัจจุบัน ประวัติล่าสุด และรายชื่อผู้ตรวจ สำหรับโหลดข้ามเครื่อง โดยสต๊อกปัจจุบันไม่ถูกล้างเมื่อขึ้นปีใหม่

แท็บประวัติเดิมไม่ถูกย้ายหรือลบ ระบบเก็บประวัติล่าสุดในแอป 200 ครั้ง ส่วนรายการตรวจที่ส่งสำเร็จยังอยู่ในแท็บปีงบประมาณ ระบบตรวจ Log ID เพื่อป้องกันข้อมูลซ้ำเมื่อคำขอเดิมถูกส่งซ้ำ

ข้อความบันทึกในเครื่องไม่ได้หมายความว่า Google Sheet บันทึกสำเร็จเสมอไป หากยังยืนยัน Google Sheet ไม่ได้ ให้ตรวจการ deploy และสิทธิ์ไฟล์ สถานะร่วมยังเป็นการเขียนข้อมูลทั้งชุด จึงควรหลีกเลี่ยงการแก้พร้อมกันหลายเครื่อง

## ตรวจสอบโค้ด

รัน `node --test tests/stock.test.cjs` เพื่อตรวจการย้ายชื่อหน่วย ข้อมูลตั้งต้น ขอบเขตปีงบประมาณ และการบันทึกแยกปีโดยไม่ซ้ำ

## วิธีใช้งาน

เปิดไฟล์ `index.html` ในเบราว์เซอร์ได้ทันที

ข้อมูลจะถูกเก็บในเครื่องผ่าน `localStorage` ของเบราว์เซอร์ แนะนำให้กด `ส่งออก` เป็นไฟล์ JSON เป็นระยะเพื่อสำรองข้อมูล

รายการตั้งต้นถูกดึงจาก Google Sheet และบันทึกไว้ใน `seed-data.js` ถ้าเปิดครั้งแรก ระบบจะโหลดรายการเหล่านี้ให้อัตโนมัติ

## Telegram

กดปุ่มตั้งค่ามุมขวาบน แล้วกรอก:

- Bot Token จาก BotFather
- Chat ID ของผู้รับหรือกลุ่ม

ถ้าส่ง Telegram ไม่สำเร็จ ระบบจะคัดลอกข้อความแจ้งเตือนให้ เพื่อนำไปวางส่งเองได้ทันที
